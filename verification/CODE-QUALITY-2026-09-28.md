# 代码质量审查与重构 · 2026-09-28

本轮在上一轮性能优化的工作区上继续审查，重点覆盖播放器状态与学习模式切换、查词与缓存、存储队列、字幕导入与检索、后台任务取消以及控制／渲染线程边界。

## 已确认并修复的问题

### P2：独立偏好文件依赖 SQLite 成功打开

原 `StorageWorker` 将文件写入也包装为数据库操作，清空待执行队列后先打开数据库。因此 `library.sqlite` 损坏时，同批 `viewing.json` 等文件保存直接丢失；单纯保存文件还会创建不需要的数据库。待写文件失败也会阻止原本可以成功的数据库读取。

现在每项任务按自身需要访问文件或数据库。批处理逐项执行，失败通过统一回调上报，其他任务继续完成；读取先处理已排队的写入，并单独返回读取结果。`flush()` 只等待队列中的操作，不再为了文件写入建立 SQLite 连接。错误回调的跨线程读写使用锁保护。

新增回归使用实际损坏的 SQLite 文件、不可写的目标路径以及同批有效操作，验证错误仍被报告、可完成的偏好写入和数据库读取仍成功，保存合并与读取顺序保持一致。

### P2：词库读取失败被当作“未收录”

原 `ECDictionary.query` 对 SQL prepare／step 的错误返回 `nil`。这与正常的查无结果无法区分，并可能被上层当作负查询结果缓存。

现在只有 `SQLITE_DONE` 表示未找到词条；SQL 准备、绑定或读取失败会抛出 `DatabaseError`，界面显示读取失败且不写入缓存。词形候选按顺序查询，找到结果后即返回。测试通过在词典实例打开后移除数据表复现原错误，同时保留大小写、弯引号、词形回退和换行文本检查。

## 必要的职责拆分

新增 `DictionaryLookupController`，统一拥有词库实例、当前选择、任务标识、取消句柄、状态更新和 256 项查询缓存。它支持注入 `LearningContentProvider`，可以用受控的异步实现精确测试请求返回顺序。`AppModel` 只提交当前选择、可见性和词库路径；关闭词卡、切换学习模式、设置更新和退出时调用控制器的统一接口。

成功和失败回调都校验任务取消与请求标识；隐藏词卡取消请求并保留可复用缓存，离开学习模式或更换词库清除缓存。延迟返回的旧请求无法写入新词条、错误状态或缓存。正常命中和未收录结果仍可同步复用，查询错误不进入缓存。`LearningContentProvider` 明确要求 `Sendable`，SQLite 词典实现移入独立的 `ECDictionary.swift`。

README 中“渲染在主线程”的过时说明已修正，当前控制与渲染各自在独立串行队列执行。
