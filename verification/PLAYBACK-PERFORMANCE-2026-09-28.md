# 播放刷新与查词性能优化 · 2026-09-28

## 改动

- 将播放位置拆到独立的可观察对象和进度条视图，时间更新不再重建整条控制栏。暂停、音量、速度等状态仍更新控制按钮；上一句、下一句和循环的可用性只在实际变化时通知界面。
- 为当前词典保留最多 256 个内存查询结果，包含未收录词。按插入顺序淘汰旧记录；命中时同步展示释义，减少重复查询以及词卡的清空、重填。切换词典设置、重新初始化词典或退出学习模式时清空缓存；异步查询仍检查取消和请求标识。
- 性能脚本在导入测试英文后取消并等待对齐任务，再安装合成单词时间，避免学习模式启动的异步任务清空测试数据。优化前后都采用这一修正，并校验真实高亮数量。
- 反馈计时探针随进度条移动，继续覆盖快进、后退的原生界面更新。

## 测量方法

基准为 `f779f2d`，仅加入相同的测试准备顺序修正及词卡重建计数。两版本均为 Release，使用相同运行结构，在 macOS 15.8 的 Intel Mac 上按“优化前、优化后、优化前、优化后”顺序各测两轮。计时期间不运行编译、其他回归测试或线程采样。

使用同一个 960×540、24 fps、30 秒 MPEG-4 合成视频，各 5,000 条英文／中文字幕及前 20 句的 180 个合成单词时间。每场景稳定 1 秒后采样约 6 秒，单独配置目录、静音播放。CPU 只统计应用进程，单核占满为 100%；不含 WindowServer 或对齐子进程。刷新次数按实际采样时间换算成每秒次数。

此负载反复使用同一句、9 个不同单词，适合验证重复查词和逐词界面更新，缓存收益不能直接外推到所有影片。合成单词时间不用于评价对齐精度。

## 结果

以下为两轮均值。CPU 百分比以单核为基准；主线程延后 P95 来自 50 ms 定时唤醒，不等同于鼠标输入到屏幕显示的延迟。

| 场景 | CPU 优化前 | CPU 优化后 | 唤醒延后 P95 前／后（ms） |
|---|---:|---:|---:|
| 沉浸播放 | 22.4% | 22.5% | 10.5 / 8.3 |
| 显示控制栏 | 33.3% | 29.3% | 13.4 / 12.0 |
| 学习侧栏 | 50.8% | 37.3% | 25.4 / 20.8 |
| 字幕全文 | 37.5% | 35.8% | 14.5 / 11.9 |

| 界面工作量 | 优化前（次/秒） | 优化后（次/秒） | 减少 |
|---|---:|---:|---:|
| 显示控制栏场景：整条控制栏重建 | 8.07 | 1.56 | 80.7% |
| 学习侧栏场景：词卡重建 | 12.66 | 7.15 | 43.5% |

此重复单词负载下，学习侧栏 CPU 相对降低 26.6%。优化后每轮学习场景仅新增 2 次词库查询，其余查询命中内存缓存。沉浸播放基本持平，不计作性能收益；字幕全文的改善较小，仍受系统负载影响。

所有场景均持续播放，超过 100 帧，保持 180 个单词时间且高亮超过 20 个不同单词。隐藏控制栏及非全文场景的原生表格更新检查均通过。

## 验证与复现

Swift 测试 110/110（17 组），Python 测试 10/10，最终 Release 原生检查 80/80（76 项播放检查、4 项重启检查）。新增测试覆盖时钟通知隔离、相同位置不重复发布、句子按钮可用性变化、正／负查询缓存、容量淘汰与清空。原生检查覆盖真实进度拖动、句子边界按钮、快进反馈计时、重复词卡即时显示、退出学习清空缓存及原有字幕／截图／重启恢复。
