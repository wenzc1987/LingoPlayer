# 窗口、设置与文件选择响应优化 · 2026-09-28

LingoPlayer 0.3.1 build 12。基准为本轮开始时的 build 11 工作区，包含字幕偏好功能；基准与优化版使用相同计时入口，均为 Release 构建。本机为 Intel Mac、macOS 15.8。

## 定位和改动

线程采样复现了主线程在 Core Animation 提交阶段，经 `_NSOpenGLViewBackingLayer.display → NSOpenGLContext.view → CGLLockContext` 等待视频渲染的情况。渲染线程同时在执行 GPU 绘制、着色器编译或提交帧。

新增 `VideoOpenGLContext` 缓存弱引用形式的关联视图，让只读视图查询不必等待 CGL 渲染锁。关联仍通过父类 setter 设置，清除 drawable 时同时清理缓存；实际 GL 绘制、尺寸更新和销毁继续使用原有串行队列和同步。视频解码、帧定时、垂直同步和播放时钟未改动。优化后的采样不再出现上述视图 getter 等待链。

设置页保留表单实例和未保存草稿，页签选择局限在设置视图中，避免发布到整个播放器模型；钥匙串读取改到后台完成。快捷键录入在离开页签时取消。播放设置的两个页面也保留实例。

视频、字幕和运行环境文件选择统一使用异步面板，并复用面板实例；每次明确重置文件类型与多选选项。文件窗口内禁止播放器快捷键及快捷键录入。面板附着于主窗口或当前设置／搜索 sheet，避免依附正在关闭的 popover；从字幕搜索进入手动导入后，取消会回到搜索页。

拖动窗口过程中不持续写入窗口尺寸，原生拖动结束后保存。应用包包含原有多尺寸 `.icns` logo；构建时使用明确的图标文件名，并通过 Launch Services 注册和刷新当前应用包。已检查 `NSWorkspace.icon(forFile:)` 返回正确 logo，签名仍有效。

## 同条件测量

使用同一个本地 1080p、30 fps、60 秒 MPEG-4 测试图视频。每种缩放状态进行 180 次真实窗口尺寸变化，宽度 980–1300、高度 640–820；以 10 ms 主线程计时器记录超时。设置页各切换 12 次，目标辅助功能查找在计时区间外；切换耗时包含下一轮 UI 提交。文件选择各打开并取消 3 次，以窗口实际可见时间衡量。最终对比不同时运行线程采样或编译任务。

| 场景／指标 | 优化前 ms | 优化后 ms |
|---|---:|---:|
| 播放中缩放：主线程停顿 P95 | 99.5 | 42.7 |
| 播放中缩放：主线程最大停顿 | 285.3 | 77.6 |
| 播放设置页签：最长切换耗时 | 1003.7 | 138.0 |
| 完整设置页签：最长切换耗时 | 294.2 | 197.8 |
| 视频文件窗口：首次可见 | 1233.9 | 1242.3 |
| 视频文件窗口：后两次平均可见 | 495.1 | 322.2 |
| 字幕文件窗口：三次平均可见 | 322.8 | 325.1 |

暂停时缩放没有明确改善：主线程 P95 为 37.4→45.2 ms，最大为 86.9→102.6 ms。首次文件窗口仍有约 1.2 秒的系统初始化开销，字幕文件窗口显示耗时基本不变。异步面板解决的是浏览期间播放状态持续更新及嵌套模态循环问题，不能将其调用返回时间等同于窗口打开速度。

以上是短场景实测，受系统负载、驱动缓存和温度影响；不代表所有片源、显示器或机器，也不等同于硬件输入到屏幕的端到端延迟。原生尺寸变化覆盖实际布局与渲染路径，未测量用户鼠标拖动事件本身。

## 真实片源与验证

额外使用本机 1080p HEVC 10-bit 影片测试最终版：播放中缩放主线程 P95 为 25.5 ms、最大 57.6 ms；播放设置和完整设置页最长切换分别为 152.6 ms、159.1 ms。此处没有同片源的优化前对照，不计算改善百分比。

两种片源各通过 14 项检查，涵盖加载与持续绘制、页签操作、文件窗口打开和取消、播放时钟继续更新、设置草稿保留、重复打开、嵌套 sheet 归属及快捷键隔离。使用独立数据目录、静音播放，没有修改用户观看记录。逐词对齐在交互测量中停用，不能据此评价对齐精度或后台对齐吞吐量。

Swift 核心测试 67/67，Python 测试 10/10；原生检查共 152/152：两种片源交互 28、字幕偏好与重启 28、播放界面回归 61、快捷键焦点 35。覆盖全屏进出、恢复窗口尺寸、大字号长字幕、时间偏移、原有反馈及退出保存。

另外运行了 5,000 条中英字幕与合成单词时间的四种持续播放场景，均满足视频绘制、高亮更新及后台表格停止刷新检查。进程 CPU 占用（单核为 100%）分别为沉浸 24.2%、操作面板 33.7%、学习侧栏 56.5%、字幕全文 38.7%。学习侧栏仍是其中开销最高的场景；本轮没有对这四种场景重做优化前 CPU 基准，因此不据此宣称 CPU 下降。
