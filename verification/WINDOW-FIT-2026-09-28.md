# 无黑边与播放设置响应 · 2026-09-28

LingoPlayer 0.3.1 build 13。对照为已提交的 `9f3cba7`（build 12），仅为对照加入相同的播放设置打开计时入口；两者均为 Release。本机为 Intel Mac、macOS 15.8。

## 结果

| 场景／指标 | build 12 | build 13 |
|---|---:|---:|
| 播放设置首次可见 | 1409.2 ms | 264.5 ms |
| 播放设置后续三次平均可见 | 1174.0 ms | 165.2 ms |
| 播放中缩放：主线程停顿 P95 | 27.0 ms | 24.2 ms |
| 播放中缩放：主线程最大停顿 | 51.3 ms | 50.5 ms |
| 暂停中缩放：主线程停顿 P95 | 39.5 ms | 41.2 ms |
| 暂停中缩放：主线程最大停顿 | 200.2 ms | 160.4 ms |
| 播放设置页签：最长切换 | 138.1 ms | 173.5 ms |
| 高级设置页签：最长切换 | 203.6 ms | 162.5 ms |

设置打开的改善明显；连续缩放改善较小，暂停时 P95 没有改善，不能宣称已达到所有场景下流畅的 60 fps。字幕外观页改为按需创建，其首次切换也计入页签耗时，存在上表中的取舍。第一次系统文件选择窗口仍约 1.2 秒，本轮未改变这条路径。

采用同一本地 1080p、30 fps、60 秒测试视频。打开弹层时记录实际窗口可见并完成布局的时间，首次打开前没有访问该弹层；共打开四次。窗口缩放每组 180 步，以 10 ms 主线程计时器记录超时。页签各切换 12 次，辅助功能节点查找放在操作计时之外。基准及最终测量均未同时运行编译和线程采样；这是本机短场景结果，存在负载、缓存及温度波动。

额外使用真实 1080p HEVC 10-bit 影片验证最终包：播放设置首次 265.3 ms，后续平均 184.3 ms；播放中缩放停顿 P95 为 17.7 ms、最大 46.5 ms。这组没有同片源的本轮基准，不用于计算改善百分比。

## 实现与行为

- 播放设置原先每次打开都会创建两个页面，字幕外观滑杆还会构造大量刻度。现在首次进入外观页才创建，之后在该弹层中保留；滑杆去掉密集刻度，取值继续按原单位舍入。字幕偏移仍使用 0.1 秒步进、停止调整 1 秒后应用。
- 缩放采样显示，片名背景渐变在主线程反复进行 Core Graphics 位图绘制。改用 `CAGradientLayer`，保留相同方向和透明度，让 Core Animation 调整尺寸。视频 view 的尺寸、原点和布局通知合并到同一轮最终几何值；drawable 更新使用 common run-loop modes，保持在拖动事件循环中执行。GL 串行化、解码、视频帧定时与垂直同步机制保留。
- “播放设置 → 时间与播放 → 无黑边”按视频实际显示尺寸、像素比例与旋转计算窗口比例，扣除可见侧栏的 333 pt。拖动时维持视频区域比例，开启、切换影片和展开侧栏时适配当前屏幕；关闭功能恢复普通窗口的自由比例。全屏沿用屏幕大小，退出后恢复影片比例。
- 开关及窗口尺寸写入已有观影偏好；旧数据默认关闭。停止播放清除影片尺寸约束。窗口最小尺寸交由 delegate 限定；根布局明确使用窗口给定的区域，避免超宽影片的小窗口被隐藏侧栏的布局需求撑开。窄窗口使用双行控制按钮。
- 无黑边完整显示视频，不裁切内容；编码在影片里的黑边保持不变。

## 验证

Swift 核心测试 70/70、Python 10/10。最终 Release 原生检查 183/183：两种片源的交互检查 30，窗口模式及重启 29，字幕偏好及重启 28，播放界面 61，快捷键 35。应用严格签名验证通过。

窗口测试使用真实 16:9、含旋转元数据的 9:16、像素宽高比 2:1 的 32:9 视频；检查开关、横向／纵向缩放、侧栏、紧凑按钮可见性、停止播放、全屏往返和新进程恢复。截图检查了横屏、竖屏及超宽画面。

另在 AppKit 的 event-tracking run-loop 中以计时器连续改变窗口尺寸 2 秒，实际绘制了 60 帧，确认 drawable 更新不会等拖动事件循环结束才继续。该检查与缩放基准都通过代码驱动几何变化，未测量硬件鼠标输入到屏幕的端到端延迟。
